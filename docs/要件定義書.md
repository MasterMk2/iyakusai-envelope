- 読者: 現役委員・**後輩委員**・開発を手伝うAI

## 1. 背景 — なぜ作るのか

2026-08-27〜28、協賛請求書25通の発送で**封筒への直接印刷**が必要になり、Pythonスクリプトに座標をハードコードしてPDFを生成した(`渉外課/請求書/【AI】封筒印刷_*.pdf`)。発送自体は成功したが、次の問題が残った。

| 起きたこと | 記録 |
|---|---|
| 座標調整が「スクリプトを直す→出力→目で見る」の繰り返しで、委員長と一晩かかった | やることリスト 2026-08-27 |
| 窓付き封筒で宛名が**窓の下端ギリギリ**になり、実物を封入した写真で初めて発覚。原因は用紙サイズの指定漏れ | 同上「教訓: 印刷して封筒に入れる成果物は用紙サイズを明示指定すること」 |
| 窓位置を決めるため**校正シートを刷って窓から見えた文字を報告**する運用が必要になり、そこで止まった | 同 未完了TODO |
| 速達マークの位置を最初に間違えた(縦長=右上部 / **横長=右側部**) | 同 修正済み |
| 作った本人(AI＋委員長)以外は再現できない。**後輩に渡せない** | — |

封筒作業は今後も繰り返し発生する。

- 領収書15社分の封筒作業(9月以降・紙前提で見積もること)
- 外部(非公認)団体の契約書郵送(1団体2通＋返信用封筒)
- 協賛依頼(80社規模の実績あり)

**毎回スクリプトを書くやり方は持続しない。** 委員が自分で位置を合わせて刷れる道具にする。

---

## 2. 目的(ゴール)

1. 委員が**封筒の絵を見ながらGUIで宛名の位置を決め**、その場でPDFを作って印刷できる
2. 決めた位置は**テンプレートとして保存**され、次回は読み込むだけで済む
3. 印刷して実物とズレたら、**ズレをmmで入れるだけ**で直る(スクリプトを触らない)
4. **後輩が引き継げる**: インストール不要・URLを開けば使える・直し方が文書にある

### ゴールでないこと (Non-Goals)

- 封筒デザインそのものの制作(Illustrator入稿データ) → 引き続き広報課・印刷会社
- 宛名リストの管理・名寄せ・敬称の判断 → 引き続きスプレッドシート側の仕事
- 郵便料金の計算・発送管理・追跡
- 汎用DTPソフトを目指すこと(何でもできる代わりに誰も使えなくなる)

## 7. 印刷精度の担保(この道具の生命線)

封筒印刷は**1mmのズレが窓から見えるか否か**を決める。次を仕様として固定する。

1. **PDFのページサイズ = 封筒実寸**。用紙に合わせる縮小をさせない(8月の事故原因はここ)
2. 印刷時は **「実際のサイズ」/「カスタム倍率 100%」・「用紙に合わせる」OFF** を必須手順として画面と手順書に明記
3. **校正ページ**を標準で用意する。内容:
   - 封筒の四隅から一定距離の**十字マークと目盛り**
   - **100mm のスケールバー**(定規で測り、100±0.5mm でなければ縮尺がおかしい=印刷設定を直す)
   - 窓に見えるはずの位置に**座標入りの格子**(窓から何が見えたかで窓位置を逆算できる。8月に作った `【AI】窓位置_校正シート` の発展形)
4. 測った値を FR-50 のオフセットに入れて反映 → 再度校正ページで確認、の**2周で合う**ことを目標にする
5. プリンタ自体の**印字不可マージン**(周囲数mm)は封筒定義に持ち、その内側に置くよう警告する

### 7.1 速達の赤線の根拠

**内国郵便約款 第98条（速達郵便物の表示）**

> 速達郵便物には、その旨を示す当社が別に定める表示をしていただきます。
> （注）当社が別に定める表示は、**その表面の右上部に朱色の横線（横に長い郵便物にあっては、右側部に朱色の縦線）を明瞭に施すもの**とします。

- **長さ・太さの数値指定は、約款にも日本郵便の案内にも無い。**要件は「明瞭に施す」だけ
- そこで**日本郵便の案内図の比率を実測**して既定値にした（[案内図](https://www.post.japanpost.jp/service/send/domestic/option/sokutatsu/)）
  - 縦長: 横線。長さ=封筒幅の約 **42%**、太さ=封筒高さの約 **2.6%**、最上部の右寄り
  - 横長: 縦線。長さ=封筒高さの約 **58%**、太さ=封筒幅の約 **2%**、右端の下寄り
- 細いと見落とされるため、**太さは最低6mm**を確保する
- この比率は `tests/test.js` で見張っている（短くすると FAIL する）

| 封筒 | 既定の赤線 |
|---|---|
| 長3窓付(横長) | 右端に **6 × 70mm** の縦線 |
| 角2(縦長) | 右上に **101 × 9mm** の横線 |

> ⚠ 2026-08に長3で位置を一度まちがえた（右上部に横線を引いた）。**長3窓付は差出人が横書きで左下にあるため横長として使う**ので、右側部に縦線が正しい。

## 9. データ仕様(案)

### 9.1 封筒定義 (`data/envelopes/*.js`)

> 中身はJSONだが、`ENVELOPE({ ... });` で包んだ `.js` として置く。
> `index.html` をダブルクリックで開いたとき(file://)、ブラウザはローカルの `.json` を fetch できないため。
> テンプレートも同様に `TEMPLATE({ ... });` で包む。

```json
{
  "id": "naga3-mado",
  "name": "長3窓付",
  "size_mm": { "w": 235, "h": 120 },
  "orientation_note": "横長で使う(差出人が横書きで左下)",
  "windows": [
    { "id": "main", "x": 13.9, "y": 12.3, "w": 90.3, "h": 45.3, "safe_margin_mm": 4 }
  ],
  "no_print_areas": [
    { "id": "flap", "note": "右のフラップ", "x": 222, "y": 0, "w": 13, "h": 120 }
  ],
  "preprinted": [
    { "id": "sender", "note": "差出人(印刷済み)", "x": 12, "y": 78, "w": 110, "h": 34 }

  "printer_margin_mm": 5,
  "source": "渉外課/長3窓付封筒_v3.pdf から算出。実物で要検証"

```

### 9.3 差し込みデータ

- 1行 = 1通。**列名は自由**、テンプレート側で `{{列名}}` として参照する
- 8月に作った `【AI】宛名データ_20260827.csv` の列構成を標準の例とする:

- 敬称の判断(「会社名 御中」か「会社名 役職 氏名 様」か)は**データ側で決める**。ツールは判断しない

- 共有ドライブ側の鉄則(既存ファイルの削除・上書き禁止、AI生成物への `【AI】` 接頭辞)は**ドライブに置くファイルにのみ適用**。GitHubリポジトリはツールの置き場であって委員会の正データではない

### 10.2 後輩への引き継ぎ(README に書くこと)

1. **使い方**: URLを開く → 封筒を選ぶ → データを読む → 位置を合わせる → 試し刷り → 本番
2. **ズレたときの直し方**: 校正ページの手順
3. **新しい封筒の足し方**: `data/envelopes/` にJSONを1つ増やす
4. **壊れたときの直し方**: AIに「このリポジトリの〜が動かない」と渡す。触っていいファイル/触らないファイルの一覧
5. **誰に聞くか**: 引き継ぎ時点の担当と連絡先

## 11. 技術構成(要件を満たす手段)

- 素のHTML + CSS + JavaScript。フレームワーク・ビルド無し
  - **ES Modules は使わない**(file:// で開いたときブラウザが `import` を拒否するため)。従来の `<script>` で読む
- PDF生成: `pdf-lib` + `@pdf-lib/fontkit` を `vendor/` に同梱
- Excel読込: `SheetJS(xlsx)` を `vendor/` に同梱(P2)
- フォント: **Zen Kaku Gothic New**(SIL OFL 1.1・静的TTF 約2.3MB)を Regular / Bold で同梱
  - 選定理由: 再配布可、**人名異体字(髙﨑濵德栁邊邉曻)を収録**、サイズが手頃
  - 未収録は全角ハイフンマイナス(－)と全角チルダ(～)の2字のみ。`App.CHAR_SUBST` で −/〜 に置換する
  - 行の基準線は **OS/2 の typo メトリクス(880/-120)** を使う。hhea(1160/-288)を使うと1行目が枠から大きく下がる
- 文字幅の計測は **fontkit に一本化**し、画面プレビューとPDFで同じ値を使う(画面で合っていれば紙でも合う)
- 保存: localStorage + JSONファイルの入出力

> 8月の実装で使った meiryo.ttc は**Windows同梱フォントで再配布不可**。Publicリポジトリには入れられないため置き換えた。
