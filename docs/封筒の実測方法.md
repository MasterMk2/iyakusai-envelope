# 封筒の実測方法(新しい封筒を足すとき)

`data/envelopes/` にファイルを1つ増やし、`index.html` に `<script>` を1行足せば新しい封筒に対応できる。その数値をどう出すかの手順。

> ファイルの中身はJSONそのものだが、拡張子は `.js` で `ENVELOPE({ ... });` で包んである。
> `index.html` をダブルクリックで開いたときにブラウザがローカルの `.json` を読めないため。

座標は**封筒の左上を原点(0,0)**、右が +x、下が +y、単位 mm。

---

## A. 入稿データ(印刷会社に出したPDF/AI)がある場合 ← いちばん正確

入稿データは封筒より大きい紙(A3やA4)の上に封筒が描かれている。**封筒の左上がその紙のどこにあるか**を先に出し、あとは引き算するだけ。

### 1. 封筒の原点を出す

寸法線(「235mm」などの矢印)の端点を読むのがいちばん確実。

```bash
py -c "
import fitz
PT=25.4/72
d=fitz.open('長3窓付封筒_v3.pdf'); p=d[0]
for dr in p.get_drawings():
    r=dr['rect']; w,h=r.width*PT,r.height*PT
    if w*h>100:
        print('%7.1f x %-7.1f x:%7.1f-%-7.1f y:%7.1f-%-7.1f %s'%(w,h,r.x0*PT,r.x1*PT,r.y0*PT,r.y1*PT,dr['type']))
"
```

- 幅235mm・高さ120mmに一致する矢印(細長い図形)の x0 / y0 が**封筒の左上**
- 2026-09の実測: 長3窓付 = (31.3, 45.0) / 角2 = (28.6, 41.1)
- 角2のように寸法線が拾えないときは、**印刷可能範囲の枠が封筒に対して上下左右対称**であることを使って逆算する(角2はこれで出し、差出人ブロックの既知の実測値と一致することを確認した)

### 2. 窓・印刷可能範囲・差出人を出す

同じ出力から、窓や枠の矩形を探して**原点を引く**。差出人ブロックはテキストの座標から出す。

```bash
py -c "
import fitz
PT=25.4/72; EX,EY=31.3,45.0   # ←1で出した封筒の左上
d=fitz.open('長3窓付封筒_v3.pdf'); p=d[0]
for b in p.get_text('dict')['blocks']:
    for l in b.get('lines',[]):
        for s in l['spans']:
            if s['text'].strip():
                x0,y0,x1,y1=[v*PT for v in s['bbox']]
                print('%-20s x:%6.1f-%-6.1f y:%6.1f-%-6.1f %.1fpt'%(s['text'][:20],x0-EX,x1-EX,y0-EY,y1-EY,s['size']))
"
```

## B. 入稿データが無い場合

1. 封筒の**外形**を定規で測る(長3=235×120、角2=240×332 のような規格寸法があるので確認)
2. 窓は**左上角からの距離**と**窓のサイズ**を測る
3. 差出人の印刷済み範囲は、外接する長方形として測る
4. 迷ったら**大きめに**とる(そこを避けて宛名を置くので、広めに申告する方が安全)

スキャナがあるなら、封筒を**原稿台の左上角に密着させて**スキャンし、画像を下敷きとして重ねて位置を読む方法もある(ツール側の下敷き機能)。

---

## C. 必ず最後に校正ページで検証する ★これを飛ばさない

入稿データの数値は**設計図であって実物ではない**。

- 印刷会社の断裁は数mmずれる
- **ロットが違うと差出人のデザインごと変わっていることがある**
  (実例: 2026-09時点の長3の実物は旧ロットで、〒930-0152・Eメール行あり。v3入稿データは〒930-0194・電話番号あり)

手順:

1. ツールの**「校正ページ」**ボタンでPDFを出し、封筒に1枚印刷する(印刷設定は「実際のサイズ」「用紙に合わせるOFF」)
2. **100mmスケールバーを定規で測る** → 100±0.5mm でなければ印刷設定が縮小している。設定を直して刷り直す
3. **十字マーク**の中心が、書かれている座標(封筒の左上からのmm)に本当にあるか測る
4. ずれていた量を、画面の「ズレの補正」に (右へ, 下へ) mm で入力する
5. **窓付き封筒なら、カギ形のマークと実物の窓を見比べる**
   - マークの内側に窓がぴったり入っていれば、封筒定義の窓の値は正しい
   - ずれていれば、刷られた目盛りで**実物の窓の左/上/右/下を読み取り**、`data/envelopes/*.js` の `windows` を直す
6. もう一度校正ページを刷って合っていることを確認する
7. `data/envelopes/*.js` の `verified_against_physical` を `true` にし、直した値をファイルに反映する

## D. 封筒定義に書くこと

| キー | 内容 |
|---|---|
| `id` | 英数字の名前(ファイル名と合わせる) |
| `name` | 画面に出る名前 |
| `size_mm` | 封筒の外形 |
| `windows[]` | 窓の位置・サイズ・安全余白(`safe_margin_mm`、既定4mm) |
| `printable_area` | ふつうに使ってよい範囲 |
| `preprinted[]` | 差出人など**印刷済みの領域**。`avoid: true` なら重なったとき警告、`avoid: false`(地紋など)なら警告しない |
| `printer_margin_mm` | プリンタが物理的に刷れない周囲の余白 |
| `source` | どのファイルの何から出した値か |
| `verified_against_physical` | 実物で確認したか(未確認なら `false` のままにする) |

既存の `naga3-mado.js` / `kaku2.js` をコピーして書き換えるのが早い。
**最後に `index.html` の「封筒定義」のところに `<script src="data/envelopes/新しい封筒.js"></script>` を1行足すのを忘れないこと。**
